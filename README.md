# 秘钥守望者（SecretWatcher）

> 守望公开互联网中的 AI API 密钥泄露，帮助资产所有者更早发现风险、更快完成处置。

## 我们为什么做这个项目

API Key 已经成为开发者和企业的重要数字资产。一旦密钥出现在公开网页、错误日志、配置接口、代码仓库或错误部署的开源应用中，任何人都可能复制并滥用它，由此产生费用损失、服务中断、数据风险和合规问题。

一些成熟平台已经建立了公开泄露发现、异常使用提醒、权限限制、用量监控和密钥失效机制。但现实中，仍有大量 AI API 密钥暴露在互联网上，泄露后长时间保持有效，资产所有者也无法及时收到通知。

我们认为：不应该等到账单异常后，用户才知道自己的密钥已经被盗用。

因此，我们发起了公益项目「秘钥守望者」。

## 我们想做什么

秘钥守望者希望建立一条持续运行的公益安全闭环：

1. 从合规的互联网测绘数据和公开页面中发现可能存在的 AI 应用与服务。
2. 识别公开暴露的 API 密钥、访问令牌及相关敏感配置。
3. 在不使用、不验证泄露密钥的前提下，对风险进行脱敏、去重和人工复核。
4. 寻找资产所有者公开提供的安全联系渠道。
5. 向资产所有者和相关 API 服务提供方发送负责任披露通知。
6. 跟踪通知、确认、轮换、失效和误报处理结果。
7. 总结共性问题，推动平台和开源项目建立更完善的密钥保护机制。

DeepTutor 是我们已经验证的一类公开配置泄露场景，但它不是项目的边界。未来我们将逐步研究更多 AI 应用、开发框架、代理网关和常见错误部署方式，并支持识别更多 AI 服务提供方的凭据风险。

## 公益原则

这是一个公益安全项目。

- 不出售发现的密钥或泄露数据。
- 不使用泄露密钥调用任何第三方 API。
- 不通过余额查询、模型调用或其他请求验证密钥是否有效。
- 不公开仍可能有效的完整密钥、个人信息或可直接利用的目标清单。
- 不绕过登录、权限控制或其他访问限制。
- 只处理公开可访问、与防御目的直接相关的最小必要信息。
- 优先通知和修复，而不是展示、炒作或排名。
- 接受资产所有者的误报申诉与数据删除请求。

## 数据保护

正式系统将遵循“最少采集、最短留存、默认脱敏”的原则：

- 完整密钥不进入普通数据库、日志、报告或导出文件。
- 使用不可逆指纹进行去重和事件关联。
- 对外仅展示必要的脱敏片段、发现时间和泄露位置。
- 对证据设置访问控制、审计记录和自动过期策略。
- 未经授权，不对发现的凭据进行有效性测试。

## 项目计划

第一阶段将聚焦于公开暴露的 AI API 凭据：

- 建立互联网资产发现和应用指纹体系。
- 覆盖多种 AI 应用和多家 API 服务提供方，而非只检测单一项目。
- 建立人工复核、资产归属调查和通知工作流。
- 建立安全的证据处理、事件跟踪和误报处置机制。
- 发布经过脱敏的研究结论和面向开发者的修复建议。

长期目标包括：

- 扩大公益监测节点和服务器资源。
- 为自愿接入的用户提供用量异常、来源变化和费用风险提醒。
- 与 API 服务提供方建立标准化泄露报告和处置回执机制。
- 推动更多平台实现公开泄露自动识别、通知、限制和密钥轮换。

项目发起人会持续投入更多服务器资源，但扫描规模不会优先于安全边界、准确率和负责任披露质量。

## 负责任披露

如果你收到秘钥守望者发送的通知，它只意味着我们在公开位置发现了疑似凭据暴露，不代表我们使用过该凭据。建议立即：

1. 在对应平台禁用或轮换密钥。
2. 检查调用日志、来源 IP、模型使用和费用变化。
3. 删除公开位置中的凭据，并检查历史版本、缓存和镜像。
4. 为不同应用和环境使用独立、最小权限的密钥。
5. 设置速率、来源、权限和消费限制。

报告安全问题时，请不要在公开 Issue 中提交完整 API Key、个人信息或仍可直接利用的目标。请优先使用 GitHub 的私密漏洞报告功能；在私密渠道建立前，只提交已经完全脱敏的信息。

## 参与项目

项目处于早期建设阶段。我们欢迎以下方向的公益贡献：

- AI 应用及服务的安全指纹研究
- 凭据格式和误报排除规则
- 负责任披露与通知模板
- 数据保护、合规和伦理建议
- 国际化和多语言通知
- 面向开发者的安全配置指南

所有贡献都必须遵守本项目的防御性定位和数据保护原则。

## English summary

SecretWatcher is a public-interest security project dedicated to finding AI API credentials exposed on the public internet and responsibly notifying affected asset owners and service providers. We do not use or validate leaked credentials, publish live secrets, bypass access controls, or sell discovered data. Our goal is to build a sustainable workflow for detection, verification, notification, remediation, and long-term prevention.
